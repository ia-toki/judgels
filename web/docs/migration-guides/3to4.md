# Migrating from v3 to v4

:::caution Draft
v4 is not released yet. This guide is a draft and will grow as v4 changes land.
:::

### A. Migration overview

Below is a table summarizing the differences between v3 and v4.

|Area|v3|v4|
|----|--|--|
|User registration (on/off, reCAPTCHA, activation email)|`judgels-server.yml` (`userRegistration_*` variables)|Database (Admin tab → Settings)|
|User password reset (on/off, request and reset emails)|`judgels-server.yml` (`userResetPassword_*` variables)|Database (Admin tab → Settings)|
|User registration web config API field|`useRecaptcha`|`recaptchaEnabled`|
|Training (courses, problems, submissions)|On when `app_mode` is `TLX`|On when `training_enabled` is `true`|
|Ratings|On when `app_mode` is `TLX`|On when `training_enabled` and `training_rating_enabled` are both `true`|

As with the v2 to v3 migration, we can upgrade in place, reusing the same VMs and database.

### B. Deploying Judgels v4

1. Pull the latest Judgels repository:
   ```
   cd ~/judgels
   git pull
   ```
1. Keep the `userRegistration_*` and `userResetPassword_*` variables in `env/vars.yml` for now. On its first start, v4 copies them into the database (see section C).
1. In `env/vars.yml`, replace `app_mode` with the training flags (see section D). If `app_mode` was `TLX`:
   ```
   training_enabled: true
   training_rating_enabled: true
   ```
   If `app_mode` was unset or `JUDGELS`, remove it; both flags default to `false`.
1. Set the Judgels version in `env/vars.yml`:
   ```
   app_version: '4.0.0'
   ```

Then, run the deploy playbook:

```
cd deployment/v3-ubuntu-24.04/ansible
ansible-playbook -e @env/vars.yml playbooks/deploy.yml
```

### C. User registration and password reset settings

User registration and password reset are now turned on and configured in the Admin tab, under System → Settings, instead of in `judgels-server.yml`. The `mailer` and `recaptcha` config stay in `judgels-server.yml`, because they hold secrets.

On its first start, v4 copies the old values into the database, so nothing needs to be re-entered:

- If `userRegistration_enabled` is `true`, the registration settings are copied: enabled, reCAPTCHA (from `userRegistration_useRecaptcha`), and the activation email template.
- If `userResetPassword_enabled` is `true`, the password reset settings are copied: enabled, and the request and reset email templates.
- A feature that is turned off in the config is not copied, and stays off.
- Settings that already exist in the database are never overwritten, so later restarts do not undo changes made in the Admin tab.

After the upgrade, the Admin tab is the only place to change these settings. The `userRegistration_*` and `userResetPassword_*` variables are deprecated, and will be removed in the release after v4.0. Once v4 has started once, they can be removed from `env/vars.yml`.

Saving these settings in the Admin tab is rejected when:

- registration or password reset is turned on, but no `mailer` is configured;
- reCAPTCHA is turned on, but no `recaptcha` is configured;
- the activation email body or the password reset request email body does not contain `{{emailCode}}`.

### D. Training and rating flags

v3 had two modes: `JUDGELS` and `TLX`. Training and ratings were on only in `TLX` mode. v4 has no modes; each feature has its own flag instead:

- `training_enabled` turns on training: courses, the problem and submission lists, the training admin pages and role, and the submission history on profiles.
- `training_rating_enabled` turns on ratings: the Ranking page, the top ratings on the home page, the Ratings admin page, and rating contests. Ratings are only on when training is also on.

Both default to `false`. `app_mode` is no longer read, so a `TLX` deployment that only bumps `app_version` loses training and ratings after the upgrade.

Without Ansible, make the same change by hand:

- In `judgels-server.yml`, remove `judgels.app`, and set the flags in the top-level `training` block. The server no longer starts if `judgels.app` is still there.
  ```yaml
  training:
    enabled: true
    rating:
      enabled: true
  ```
- In `judgels-client.js`, replace `mode` with:
  ```js
  training: { enabled: true, rating: { enabled: true } },
  ```

### E. Verifying

1. Log in as `superadmin`, and go to the Admin tab, then System → Settings. Verify that the User registration and User password reset sections match the old config.
1. Log out. Verify that the Register link and the "Forgot your password?" link show only when their feature is turned on.
1. If registration is turned on, register a new user, and verify that the activation email arrives.
1. Verify that the Courses, Problems and Submissions menus show only when `training_enabled` is `true`, and the Ranking menu only when `training_rating_enabled` is also `true`.

At this point, Judgels v4 should be fully operational.
